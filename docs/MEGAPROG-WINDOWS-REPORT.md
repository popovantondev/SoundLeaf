# MegaProg: локальная проверка Windows

Дата: 2026-10-01. Проверяемый проект: SoundLeaf 3.0.1, Windows x64.

Проверялся именно локальный runner MegaProg 2.0.18, а не весь набор его функций. Версию для macOS и исходники MegaProg не изменяли.

## Предыдущий выпуск 3.0.0

- Четыре полных последовательных вызова `verify` завершились успешно: `ok=true`, код 0, без тайм-аута.
- Состав проверок рос при исправлениях: 62 → 63 → 64 → 64 проверки ядра; финально также 97 проверок значков и 138 проверок панели.
- За четыре прогона выполнено 253 проверки ядра, 388 проверок значков, 480 проверок панели, 216 рендеров и 12 живых сценариев записи.
- Runner корректно запустил Windows PowerShell, компилятор .NET Framework, FFmpeg и оконный EXE без CLI; сохранил структурированный результат и текстовый журнал.
- Путь проекта передавался как отдельный аргумент. Рабочая папка runner содержала пробелы и Unicode; проект находился вне OneDrive.
- Настроенный предел полного прогона — 300 секунд. Ограничения дочерних FFmpeg-процессов проверяются самим проектом отдельно.

## Исправление 3.0.1

- Шесть полных вызовов `verify`: три промежуточных отказа и три успешных прогона после исправлений. Отказы не выдавались за успешную проверку или установку: два выявили дефекты/нестабильность UI-тестирования, один — пропущенный исходник в сборке UI-тестов. Ни один не завершился тайм-аутом.
- Успешные прогоны: 64 / 65 / 66 проверок ядра; по 97 проверок значков; 28 220 / 28 225 / 28 405 UI-проверок. Суммарно в этих трёх успешных прогонах: 195 проверок ядра, 291 значков, 84 850 UI-проверок, 540 рендеров панели и 9 живых сценариев MKV/Opus/WAV. Неуспешные и отдельные диагностические запуски в эту сумму не входят.
- Итоговый runner: `ok=true`, код 0, без тайм-аута. Проверены три языка, две темы, масштабы 100/150/200%, высоты 520/350/260, дочерние границы, пересечения и достаточная высота строк текста.
- Геометрия разных экранов и DPI моделировалась. Настоящие проверки отдельно включили Shell_NotifyIconGetRect, DPI текущего монитора, фокус, списки и жизненный цикл анимации. Два снимка настоящего окна на чёрной подложке подтвердили сглаженные углы Windows 11 в обеих темах.
- Исправлены захват служебной рамки в изображение анимации, высота строк, подстановка короткого перевода внутрь `mono`, UTF-8 диагностики и завершение тестового оконного потока. Кодирование аудио и папки существующих записей не менялись.
- История Git дополняется отдельными коммитами; загрузки на GitHub нет. Установка — отдельный этап после runner, с проверкой отсутствия работающего экземпляра, общего mutex и резервной копией EXE.

## Что улучшить в MegaProg на основании этого опыта

1. Показывать ход длинной проверки: имя текущего сценария, прошедшее время и последний вывод. Сейчас пользователь может принять ожидание итогового JSON за зависание.
2. Сохранять историю отчётов по идентификатору запуска, а не только последние `verification.json` и `verify-0.log`; связывать её с Git-коммитом и хешем проверенного EXE.
3. Отдельно отмечать проверки, которые реально включают системный звук или окно, и получать согласие перед первым запуском таких сценариев.
4. Разделять итоговые статусы: сборка, синтетические тесты, UI-рендеры, живой сценарий, установка. Успешная команда проверки сама по себе не подтверждает обновление установленного EXE.
5. Для Windows readiness включить Unicode/пробелы, отсутствие SDK при использовании Framework-компилятора, доступность FFmpeg-кодеков и запуск GUI без консоли.

Это предложения, не утверждение о наличии ошибок во всех этих функциях. GUI MegaProg, передача задач, повторные попытки, аварийное завершение runner и работа на другом Windows-компьютере в этом прогоне не проверялись. Детали приложения и ограничения: [VERIFICATION.md](VERIFICATION.md).
