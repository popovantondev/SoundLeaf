# MegaProg: локальная проверка Windows

Дата: 2026-10-01. Проверяемый проект: SoundLeaf 3.0.3, Windows x64.

Проверялся именно локальный runner MegaProg 2.0.18, а не весь набор его функций. Версию для macOS и исходники MegaProg не изменяли.

## Предыдущий выпуск 3.0.0

- Четыре полных последовательных вызова `verify` завершились успешно: `ok=true`, код 0, без тайм-аута.
- Состав проверок рос при исправлениях: 62 → 63 → 64 → 64 проверки ядра; финально также 97 проверок значков и 138 проверок панели.
- За четыре прогона выполнено 253 проверки ядра, 388 проверок значков, 480 проверок панели, 216 рендеров и 12 живых сценариев записи.
- Runner корректно запустил Windows PowerShell, компилятор .NET Framework, FFmpeg и оконный EXE без CLI; сохранил структурированный результат и текстовый журнал.
- Путь проекта передавался как отдельный аргумент. Рабочая папка runner содержала пробелы и Unicode; проект находился вне OneDrive.
- Настроенный предел полного прогона — 300 секунд. Ограничения дочерних FFmpeg-процессов проверяются самим проектом отдельно.

## Исправление 3.0.1

- Успешные прогоны: 64 / 65 / 66 проверок ядра; по 97 проверок значков; 28 220 / 28 225 / 28 405 UI-проверок. Суммарно в этих трёх успешных прогонах: 195 проверок ядра, 291 значков, 84 850 UI-проверок, 540 рендеров панели и 9 живых сценариев MKV/Opus/WAV. Неуспешные и отдельные диагностические запуски в эту сумму не входят.
- Итоговый runner: `ok=true`, код 0, без тайм-аута. Проверены три языка, две темы, масштабы 100/150/200%, высоты 520/350/260, дочерние границы, пересечения и достаточная высота строк текста.
- Геометрия разных экранов и DPI моделировалась. Настоящие проверки отдельно включили Shell_NotifyIconGetRect, DPI текущего монитора, фокус, списки и жизненный цикл анимации. Два снимка настоящего окна на чёрной подложке подтвердили сглаженные углы Windows 11 в обеих темах.
- Исправлены захват служебной рамки в изображение анимации, высота строк, подстановка короткого перевода внутрь `mono`, UTF-8 диагностики и завершение тестового оконного потока. Кодирование аудио и папки существующих записей не менялись.
- История Git дополняется отдельными коммитами; загрузки на GitHub нет. Установка — отдельный этап после runner, с проверкой отсутствия работающего экземпляра, общего mutex и резервной копией EXE.

## Исправление 3.0.2 — полный прогон пройден

- Четыре вызова runner: первый полный завершился отказом на первом живом сценарии; второй явно запускался с `-NoLive` и успешно завершил только сборку, синтетические и UI-проверки. Третий выполнил все проверки и три живых сценария, но завершился ошибкой при фиксации SHA-256 кандидата. Четвёртый полный прогон после исправления завершился успешно: `ok=true`, код 0. Тайм-аутов не было. Частичный успех и ошибка фиксации не разрешали установку.
- В каждом вызове прошли 73 проверки ядра, 105 значков, 42 226 UI-проверок и 252 рендера. Сумма четырёх вызовов: 292 проверки ядра, 420 значков, 168 904 UI-проверки и 1008 рендеров. Третий и четвёртый вызовы выполнили суммарно 6 успешных живых сценариев MKV/Opus/WAV. В финальный вызов также входят 3 отдельные проверки переносимого SHA-256; отдельные диагностические запуски в суммы не включены.
- Первый живой отказ был реальным: Windows не передал PCM на полностью тихом выходе, пустой файл не был объявлен готовым. Для воспроизводимого прогона добавлен отдельный тестовый поток цифровой тишины; он защищён mutex, не запускается при работающем установленном рекордере, не меняет громкость и не включается обычным приложением.
- Настоящий снимок уведомления Windows подтвердил лист вместо квадрата в шапке и вместо стандартного значка у текста. Натуральный лист EXE сравнивается с ICO побайтово во всех восьми размерах. Геометрия и DPI по-прежнему разделены на моделирование и настоящие проверки текущего монитора.
- Проверена защита установщика: частичный результат отклонён до записи файлов. Финальный полный runner запущен после штатного сохранения и выхода пользователя; установленный рекордер не останавливали принудительно. Установка проверенного EXE является отдельным защищённым шагом с резервной копией, проверкой mutex и совпадением хеша кандидата.
- Обнаружено различие хостов: тип SoundPlayer тестового renderer компилируется в Framework/PowerShell 5.1, но тот же диагностический Add-Type в PowerShell 7 требует другую сборку. Настроенный runner явно использует `powershell.exe` 5.1; ошибка диагностического хоста не скрывается как успешная компиляция.
- В третьем вызове `Get-FileHash` не разрешился, хотя отдельный PowerShell 5.1 его находил. Точная причина различия обнаружения модулей не установлена; вместо предположений проект использует потоковый SHA-256 через .NET в проверке, установке и экспорте. Вектор пустого файла, ASCII `abc` и отказ отсутствующему файлу проверены; повторный полный прогон успешно создал квитанцию с хешем.
- Живой вход в финальных сценариях — неслышная цифровая тишина, а не разговор. Реально проверены устройство, пауза, повторная запись, кодировщики и сохранение. Движение индикатора при положительном уровне проверено отдельными известными PCM-данными; запись человеческой речи этим прогоном не заявляется.
- Установка завершена отдельно в 19:49 CEST: `C:\Users\Public\Player\SoundLeaf.exe`, версия `3.0.2.0`, хеш совпадает с квитанцией полного прогона. Все 8 ресурсов значка совпадают с установленным ICO; прежний EXE 3.0.1 сохранён с исходным хешем в `Backups\BeforeSoundLeaf302-20261001-194935-595834`. FFmpeg не менялся; списки файлов Recordings/State до и после совпадают по именам, размерам и времени изменения. Рекордер автоматически не запускали, поскольку обычный запуск начинает новую запись. На GitHub ничего не отправляли.

## Исправление 3.0.3 — полный прогон пройден

- Два явных вызова `verify` с `-NoLive`: первый выявил выход увеличенного индикатора за короткую карточку на 1 пиксель; второй после адаптации высоты прошёл. Оба выполнили по 73 проверки ядра, 105 значков и 3 проверки хеша: суммарно 146/210/6. Тайм-аутов не было.
- Успешный второй вызов: 42 240 UI-проверок и 252 рендера панели, плюс 4 отдельных изображения индикаторов. Незавершённые UI-проверки первого вызова не прибавляются к этому числу. Отдельная диагностика native-only: 624 проверки, вне сумм runner.
- Новые проверки различают тонкий контур и залитую полосу, подтверждают спад после тихого промежутка, пять разделённых столбиков, тишину, паузу и остановку таймера без новых пакетов. 50 мс передачи уровня и 150 мс устаревания не меняют захват или кодирование; 14/35 мс — параметры математического сглаживания, не измеренная задержка настоящего разговора.
- На этапе частичных прогонов живые циклы не запускались, поскольку установленный SoundLeaf был открыт. Частичный `ok=true` не разрешил установку: установщик отказал до записи файлов, исходный хеш EXE 3.0.2 сохранился. После штатного выхода в 20:59 и уточнения листа третий вызов выполнил полный прогон без `-NoLive`: `ok=true`, код 0, без тайм-аута.
- Финальный вызов: 73 проверки ядра, 114 значков, 3 хеша, 42 244 UI-проверки, 252 рендера и 3 настоящих цикла MKV/Opus/WAV с тестовой неслышной цифровой тишиной. Итог за три вызова: 219 проверок ядра, 324 значков и 9 хеша; успешные полные UI-матрицы второго/третьего вызовов дают 84 484 проверки и 504 рендера. Незавершённые UI-проверки первого вызова и отдельные диагностические запуски не включены.
- Лист уведомления больше не передаётся одним фиксированным размером: маленький и большой HICON создаются в точном размере DPI панели задач. Проверены 9 размеров native-иконок с прозрачностью и 4 пары размеров при 96/120/144/192 DPI. Настройки Windows не менялись: это проверка метрик, не четырёх физических дисплеев. Настоящий снимок уведомления на текущем рабочем столе осмотрен; дополнительная native-only диагностика дала 628 проверок. Значки состояний и анимация сохранения сохранены.
- macOS и исходники MegaProg не изменялись; Git дополняется новыми коммитами без переписывания истории, отправки на GitHub нет. Установка проверенного EXE — отдельный защищённый этап, не следствие одного статуса runner.

## Что улучшить в MegaProg на основании этого опыта

1. Показывать ход длинной проверки: имя текущего сценария, прошедшее время и последний вывод. Сейчас пользователь может принять ожидание итогового JSON за зависание.
2. Сохранять историю отчётов по идентификатору запуска, а не только последние `verification.json` и `verify-0.log`; связывать её с Git-коммитом и хешем проверенного EXE.
3. Отдельно отмечать проверки, которые реально включают системный звук или окно, и получать согласие перед первым запуском таких сценариев.
4. Разделять итоговые статусы: сборка, синтетические тесты, UI-рендеры, живой сценарий, установка. Успешная команда проверки сама по себе не подтверждает обновление установленного EXE.
5. Для Windows readiness включить Unicode/пробелы, отсутствие SDK при использовании Framework-компилятора, доступность FFmpeg-кодеков и запуск GUI без консоли.
6. Отличать полный прогон от явного пропуска живых проверок в итоговом статусе, даже если команда возвращает 0; связывать разрешение установки с полным результатом и хешем кандидата.
7. Показывать версию PowerShell и семейство .NET, в котором действительно выполняются сборка и проверки; не переносить выводы от PowerShell 7 на Framework 5.1.
8. Сохранять безопасную диагностику разрешения команд и путей модулей при ошибках дочернего PowerShell; не объявлять установку успешной, если финальная квитанция проверенного файла не создана.

Это предложения, не утверждение о наличии ошибок во всех этих функциях. GUI MegaProg, передача задач, повторные попытки, аварийное завершение runner и работа на другом Windows-компьютере в этом прогоне не проверялись. Детали приложения и ограничения: [VERIFICATION.md](VERIFICATION.md).
